# ข้อกำหนดขอบเขตงานและเงื่อนไขเสนอขาย

## ระบบสั่งอาหารและบริหารร้านอาหารผ่าน QR Code

**สถานะเอกสาร:** ข้อเสนอเชิงพาณิชย์ฉบับร่าง ลงวันที่ 6 พฤศจิกายน 2569  
**สมมติฐานการเสนอขาย:** ให้ถือว่าระบบตามขอบเขตนี้พัฒนาเสร็จและพร้อมส่งมอบบน Quasar + Hono + D1 + Drizzle/Cloudflare เมื่อผ่านการตรวจรับตามข้อ 11  
**ข้อเท็จจริงจาก repository:** โค้ดที่ตรวจได้ในปัจจุบันยังเป็น Quasar + Supabase/PostgreSQL; repository ยังไม่พิสูจน์ว่าระบบบน stack ใหม่เสร็จแล้ว เอกสารนี้จึงไม่ใช้แทนหลักฐานการตรวจรับหรือคำรับรองว่ามีระบบใหม่อยู่จริง

## 1. ชื่อโครงการ

จัดซื้อหรือรับบริการระบบสั่งอาหารผ่าน QR Code และระบบบริหารจัดการร้านอาหาร DEMO Bang saen

## 2. ความเป็นมา

ระบบนี้รองรับลูกค้าสั่งอาหารจากโต๊ะหรือแบบสั่งกลับบ้าน และให้ร้านจัดการเมนู คิว โต๊ะ บิล และยอดขายในที่เดียว ข้อความนี้อ้างอิงลักษณะงานที่พบในโค้ดเดิม ผู้ซื้อควรปรับชื่อหน่วยงาน ความจำเป็น และประโยชน์ที่คาดว่าจะได้รับให้ตรงข้อเท็จจริงก่อนนำไปใช้เป็น TOR ทางการ

## 3. วัตถุประสงค์

1. จัดหาระบบที่ใช้งานได้ตามขอบเขตในข้อ 5 พร้อมติดตั้งและตรวจรับ
2. เลือกสิทธิ์การใช้แบบซื้อครั้งเดียวหรือบริการรายเดือนตามข้อ 13
3. ให้ผู้ซื้อเข้าถึงและส่งออกข้อมูลของตนได้ตามเงื่อนไขสัญญา

## 4. ผู้ใช้งานและสิทธิ์

| กลุ่ม          | สิทธิ์การใช้งาน                                                                          |
| -------------- | ---------------------------------------------------------------------------------------- |
| ลูกค้า         | เข้าเมนูผ่าน QR ของโต๊ะหรือช่องทางสั่งกลับบ้าน สั่งและดูสถานะเฉพาะรอบบริการที่ตนมีสิทธิ์ |
| ผู้ใช้ฝั่งร้าน | เข้าสู่ระบบเพื่อจัดการคิว ออเดอร์ โต๊ะ เมนู บิล รายงาน และพิกัดร้าน                      |

ฐานราคานี้มี 2 กลุ่มผู้ใช้ ไม่รวมระบบกำหนดสิทธิ์ย่อยหลายระดับ เช่น เจ้าของร้าน ครัว แคชเชียร์ ซึ่งไม่มีในโค้ดเดิม การเพิ่ม role/permission ต้องประเมินเพิ่ม

## 6. สถาปัตยกรรมและเทคโนโลยี

| ชั้นระบบ        | เทคโนโลยีที่เสนอส่งมอบ                      |
| --------------- | ------------------------------------------- |
| หน้าเว็บ        | Quasar SPA และ TypeScript                   |
| API และกฎธุรกิจ | Hono บน Cloudflare Workers                  |
| ฐานข้อมูล       | Cloudflare D1 และ Drizzle ORM/migrations    |
| ภาพอาหาร        | Cloudflare R2 ตามขอบเขตนี้                  |
| การติดตามสถานะ  | polling ที่ปรับช่วงเวลาให้เหมาะกับการใช้งาน |
| โฮสต์           | Cloudflare Workers สำหรับหน้าเว็บและ API    |

D1 ใช้แนวทาง SQLite จึงต้องออกแบบกฎธุรกิจ/สิทธิ์ที่ backend ใหม่ ไม่อ้างว่า PostgreSQL RPC/RLS เดิมใช้กับ D1 ได้ตรง ๆ อ้างอิง [Cloudflare D1](https://developers.cloudflare.com/workers/databases/connecting-to-databases/), [Drizzle D1](https://orm.drizzle.team/docs/sqlite/connect-cloudflare-d1), [Hono Workers](https://hono.dev/docs/getting-started/cloudflare-workers) และ [Workers Static Assets](https://developers.cloudflare.com/workers/static-assets/)

## 7. ความปลอดภัย

API ต้องตรวจ session และสิทธิ์ทุกคำขอ จำกัดข้อมูลลูกค้าตามรอบบริการ ตรวจข้อมูลและราคาใน server จำกัดสิทธิ์อัปโหลด/ลบภาพ และบันทึกเหตุการณ์สำคัญ เช่น แก้ราคา ลบออเดอร์ และบันทึกชำระเงิน ผู้ซื้อเป็นเจ้าของข้อมูลของตน รหัสผ่านและ secret ไม่แสดงในเอกสารส่งมอบ

## 8. การเชื่อมต่อภายนอก

Cloudflare Workers/D1/R2 เป็นบริการโครงสร้างพื้นฐาน ราคาเสนอใช้หน้าตั้งค่าพิกัดแบบกรอกค่าหรืออ่านตำแหน่งจากอุปกรณ์ **โดยไม่มีแผนที่ภาพ** เพื่อให้บริการโฮสต์อยู่บน Cloudflare เท่านั้น แผนที่เดิมใช้ OpenStreetMap tile ซึ่งเป็นบริการภายนอก หากผู้ซื้อต้องการแผนที่ภาพต้องตกลงแหล่ง tile และราคาเพิ่ม Browser Geolocation, Print และ Speech อาศัยความสามารถของอุปกรณ์ ไม่รวม SSO, SMS/email, payment gateway หรือระบบบัญชี

## 9. คุณภาพการให้บริการ

เกณฑ์ตรวจรับที่เสนอสำหรับ 1 ร้าน: รองรับผู้ใช้งานพร้อมกัน 50 อุปกรณ์ และ 1,000 ออเดอร์ต่อวันในการทดสอบ UAT; API สำคัญมีเวลาตอบสนองร้อยละ 95 ไม่เกิน 2 วินาทีภายใต้ข้อมูลทดสอบที่ตกลง; สถานะคิวปรากฏบนอุปกรณ์อื่นภายใน 10 วินาทีเมื่อเครือข่ายปกติ หากข้อมูลจริงเกินขอบเขตนี้ให้ประเมิน capacity และราคาเพิ่ม กำหนดแผนสำรอง/กู้คืน D1 และทดสอบ restore ก่อนรับมอบ

## 10. การติดตั้งและส่งมอบ

ส่งมอบ environment สำหรับใช้งานจริงบน Cloudflare โดยใช้บัญชีของผู้ซื้อในแบบซื้อครั้งเดียว และบัญชีที่ผู้ขายดูแลในแบบรายเดือน จัดทำรายการ domain, binding, secrets, วิธี deploy/rollback และข้อมูลผู้มีสิทธิ์ดูแล ผู้ซื้อมีสิทธิ์รับข้อมูลของตนในรูปแบบเครื่องอ่านได้เมื่อสิ้นสุดสัญญารายเดือน

## 11. การทดสอบและตรวจรับ

1. ทดสอบ flow ลูกค้า: QR, เมนู, ตะกร้า, ส่ง/แก้ออเดอร์ และติดตามสถานะ
2. ทดสอบ flow ร้าน: login, คิว, โต๊ะ, QR, เมนู, บิล, รายงานและ export
3. ทดสอบสิทธิ์ข้ามรอบบริการ ความถูกต้องยอดเงิน การใช้งานหลายอุปกรณ์ และภาพอาหาร
4. ทดสอบ performance ตามข้อ 9 และทดสอบ backup/restore
5. ผู้ซื้อทดลองใช้งาน UAT 10 วันทำการ แจ้ง defect เป็นรายการ; ผู้ขายแก้ defect ที่ไม่ตรง TOR ก่อนลงนามตรวจรับ

## 12. เอกสารและการอบรม

ส่งคู่มือผู้ใช้ คู่มือผู้ดูแลและ backup/restore, API summary, ER Diagram, รายงานทดสอบ/UAT และอบรมออนไลน์ 2 ครั้ง ครั้งละไม่เกิน 2 ชั่วโมง แบบซื้อครั้งเดียวส่ง source code หลังชำระงวดสุดท้าย แบบรายเดือนส่งเอกสารการใช้งานและข้อมูลส่งออก แต่ไม่ส่ง source code

## 13. รูปแบบราคา สิทธิ์ และการปรับแก้

### ก. ซื้อครั้งเดียวพร้อม source code

ราคา **39,000 บาท** ไม่รวม VAT หากผู้ขายมีหน้าที่เรียกเก็บภาษี ชำระ 50% เมื่อทำสัญญา (**19,500 บาท**) และ 50% เมื่อผ่าน UAT/ส่งมอบ (**19,500 บาท**) ได้สิทธิ์ใช้งานถาวรสำหรับร้าน 1 แห่ง พร้อม source code เพื่อดูแลหรือแก้ไขใช้ภายในร้าน ลิขสิทธิ์ต้นฉบับยังเป็นของผู้ขาย; ไม่รวมสิทธิ์นำไปจำหน่ายต่อหรือให้สิทธิ์ผู้อื่น

รับประกัน defect ที่ไม่ตรง TOR **30 วัน** หลังตรวจรับโดยไม่คิดค่าแก้ไข งานปรับหน้าจอ กฎธุรกิจ หรือฟังก์ชันใหม่คิด **500 บาทต่อชั่วโมง** ขั้นต่ำ 2 ชั่วโมงต่อคำขอ โดยแจ้งประมาณชั่วโมงและขออนุมัติเป็นลายลักษณ์อักษรก่อนทำ งานหลังหมดประกันที่ไม่ได้เกิดจากข้อบกพร่องตาม TOR คิดตามอัตรานี้

ผู้ซื้อใช้บัญชี Cloudflare ของตนและชำระค่า Cloudflare/domain ตามจริงกับผู้ให้บริการ ค่าดังกล่าวไม่รวมในราคา 39,000 บาท

### ข. บริการรายเดือนพร้อมปรับแก้ต่อเนื่อง

ราคา **3,900 บาท/เดือน** ไม่รวม VAT หากผู้ขายมีหน้าที่เรียกเก็บภาษี ไม่มีค่าแรกเข้า สัญญาขั้นต่ำ **12 เดือน** ชำระล่วงหน้ารายเดือน ได้สิทธิ์ใช้งานระบบสำหรับร้าน 1 แห่งตลอดสัญญา รวมดูแลระบบและแก้ defect ที่ไม่ตรง TOR

ผู้ซื้อ **ส่งคำขอปรับแก้ได้ตลอดสัญญาโดยไม่จำกัดจำนวนคำขอ** รวมเวลาพัฒนาสำหรับการปรับแก้ในขอบเขตเดิม **4 ชั่วโมงต่อเดือน** จัดลำดับงานร่วมกัน ชั่วโมงคงเหลือสะสมได้ 3 เดือน สูงสุด 12 ชั่วโมง งานเกินกำลังพัฒนาเข้าคิวเดือนถัดไปโดยไม่เสียค่าเพิ่ม หรือหากต้องการเร่งด่วนคิด **500 บาทต่อชั่วโมง** ขั้นต่ำ 2 ชั่วโมง เมื่อผู้ซื้ออนุมัติ งานเพิ่มระบบหลัก/เชื่อมต่อภายนอก/เปลี่ยนสถาปัตยกรรมเสนอราคาแยก

รวมค่า Cloudflare ตามจริงไม่เกิน **500 บาท/เดือน**; ส่วนเกินแจ้งผู้ซื้อและเรียกเก็บตาม invoice เมื่อได้รับอนุมัติ ไม่ส่ง source code ในแพ็กเกจรายเดือน เมื่อสิ้นสุดสัญญา สิทธิ์ใช้งานสิ้นสุดและส่งออกข้อมูลของผู้ซื้อภายใน 15 วันทำการหลังชำระยอดค้างครบ

**ข้อกำหนดร่วม:** ราคาสำหรับร้าน 1 แห่งและขอบเขต 50 ฟังก์ชันในภาคผนวก ก ไม่รวมหลายร้านหรือการขายต่อ การเปลี่ยนขอบเขตต้องทำเป็นเอกสารแนบท้าย

## 14. ระยะเวลาและบริการหลังขาย

ระบบถูกเสนอขายในฐานะสินค้าพร้อมส่งมอบ ระยะเตรียมบัญชี/ติดตั้ง/ทดสอบ UAT เสนอ **20 วันทำการ** หลังได้รับ domain, บัญชี และข้อมูลตั้งต้นครบ ระยะนี้ไม่ใช่เวลาพัฒนาระบบใหม่

แบบรายเดือนให้บริการวันทำการจันทร์–ศุกร์ 09.00–18.00 น. เวลาไทย แจ้งปัญหาผ่านช่องทางที่ระบุในสัญญา ปัญหาระบบหยุดให้บริการตอบรับภายใน 4 ชั่วโมงทำการและเสนอวิธีแก้/ทางเลี่ยงภายใน 2 วันทำการ; ปัญหาทั่วไปตอบรับภายใน 1 วันทำการ กำหนดวันแก้ตามความซับซ้อน ไม่รวมการรับประกันพร้อมให้บริการตลอด 24 ชั่วโมง

## 15. งานที่ไม่รวม

Payment gateway, POS, stock ledger, SSO, SMS/email, RBAC หลายระดับ, native mobile, PDF/XLSX generator, push realtime, ระบบหลายร้าน, การย้ายข้อมูลจำนวนมากที่ไม่ทราบปริมาณ, การจัดหาฮาร์ดแวร์และค่าบริการภายนอกที่เกินขอบเขตราคา งานเหล่านี้ต้องตกลงขอบเขตและราคาเพิ่มก่อนดำเนินการ
